# 工具调用（Tool Use）

LLM 本身不能“做事”，必须调用工具

  • 什么时候调用？
  • 调哪个工具？
  • 参数怎么填？
  • 结果怎么用？

本质是：

❌ LLM 不擅长“结构化决策”

Thought → Tool Selection → Arguments → Tool Execution → Result

是一个：

决策 + API 调用问题

# 解决思路

  • Function Calling / Tool Schema
  • Toolformer / ReAct
  • Planner 决定工具序列
  • Tool feedback loop（结果再输入模型）

# 1 Function Calling / Tool Schema

把“工具”变成 LLM 能理解和调用的结构化接口

Tool Schema

{
  "name": "get_weather",
  "description": "Get weather by city",
  "parameters": {
    "type": "object",
    "properties": {
      "city": { "type": "string" }
    },
    "required": ["city"]
  }
}

Function Calling

{
  "tool": "get_weather",
  "arguments": {
    "city": "Tokyo"
  }
}

# 2 Toolformer / ReAct

ReAct

Thought: 我需要查天气
Action: get_weather(city="Tokyo")
Observation: 20°C
Thought: 可以回答了
Answer: 今天东京20°C

Toolformer

（模型训练）

核心思想：

LLM 自己学习：

  • 什么时候调用工具
  • 怎么调用

不是纯 prompt，而是：

让模型“内化工具使用能力”

# 3 Planner 决定工具序列

不让 LLM“边想边调用”，而是先规划完整工具链

ReAct 的问题：

  • 局部最优
  • 容易乱调用工具
  • 不稳定
Task: 分析数据

Planner 输出：
1. load_data()
2. clean_data()
3. analyze()
4. plot()

# 4 Tool feedback loop（结果再输入模型）

工具结果必须“反馈给模型”，形成闭环

Thought → Action → Tool → Result → Observation → Thought → ...
